# 28 — Compilers: clang-20 is bit-identical and 4.4% faster at 20 threads (12.6% single-threaded)

The same commit built three ways and compared with the harness from entry 27
(`bench/pgo_experiment.sh`, `ARMS="base gcc14 clang20"`). Commits:

- `488a74a`: an engine portability fix clang needed;
- `1245285`: per-arm compilers in the harness;
- `82ee046`: the results, in `bench/results/compilers-2026-09-24/`.

The three builds:

- **base:** g++ 13.3 (Ubuntu default), `-std=c++17 -O3 -flto -march=native -fopenmp`;
- **gcc14:** g++ 14.2, same flags;
- **clang20:** clang++ 20.1.2, same flags.

## Getting clang to build it

The developer installed `clang-20 g++-14`, then `libomp-20-dev`. The dry runs
showed only new packages and no upgrades to the libraries the benchmarks load.

1. **Variable-length array.** `Trainer` testing mode had
   `int32_t offsets[games_.size()] = {0}`. That is a GCC extension, and clang
   rejects an *initialized* VLA. It is now `std::vector<int32_t>(n, 0)`, the
   same zero-filled buffer (`488a74a`). No benchmark exercises testing mode,
   so the digests do not cover this line; it is equivalent by construction.
   Golden and verify were unchanged.
2. **OpenMP runtime.** Without `libomp-dev`, clang has no `omp.h`, and GCC's
   `omp.h` uses GCC-only attributes. I first tried
   `clang -fopenmp=libgomp` with a two-function shim header, so that both
   compilers would share GCC's runtime.
   - **It compiled, and silently dropped every OpenMP pragma.** Clang only
     emits LLVM's runtime ABI (`__kmpc_*`), which libgomp does not export.
     The give-away was 20-thread engine time 10× slower, which matches
     serial execution. The emitted IR contained no runtime calls.
   - The shim was removed. The clang arm uses **libomp** (LLVM's runtime)
     and the GCC arms use **libgomp**.
   - So at 20 threads, clang vs GCC mixes compiler and runtime. That is the
     real choice anyway. The single-threaded stub runs barely touch the
     runtime and isolate the compiler.

With libomp installed, the unmodified bench Makefile builds with
`CXX=clang++-20`. LTO works through `LLVMgold.so` and the system linker.
Clang warns about VLAs elsewhere and about defaulted assignment operators that
are implicitly deleted by `const` members; neither is an error.

## Gates: all three bit-identical

- Golden `d8f9bd2d22ee9731` / `d7581196f9d30591` and verify PASS for every
  arm.
- `SAMPLE_DIGEST` on seeds 1–4 (300 games, 1600 searches, 20 threads) matches
  the recorded baselines exactly for every arm.
- Turns were identical on every timing seed.

So clang's floating-point results agree with GCC's here: no contraction under
`-std=c++17`, and the same libm results for `sqrt` and the rest.

## Timing (paired by seed, arms back to back in rotated order)

| | clang20 | gcc14 |
|---|---|---|
| **mt engine** (real network, 20 threads, 20 × 1,000 games) | **−4.4%** (95% CI −4.9 to −4.0) | −0.4% (−1.0 to +0.1) |
| mt wall | **−26.1%** (−26.5 to −25.8) | −2.4% (−2.8 to −1.9) |
| **st engine** (stub, 1 thread pinned, 20 × 200 games) | **−12.6%** (−13.6 to −11.5) | −0.5% (−1.6 to +0.7) |

The package averaged 91 °C. Arms alternate per seed, so heat does not favour
one arm.

- **g++-14 is the same as g++-13.**
- **clang-20 is faster on the engine.** The single-threaded gain (−12.6%)
  shrinks to −4.4% at 20 threads. That is the entry-22 pattern: at 20 threads
  the memory side dominates, and a compiler cannot change that. The OpenMP
  runtime is also part of the 20-thread number.
- **Wall time −26% means the CPU network (`Mlp`) is much faster under
  clang.** The AVX2 intrinsics tile (entry 18) is presumably scheduled or
  register-allocated better. Not investigated. In production the GPU replaces
  that network, so the number that counts is engine time.
- **Clang's binary is half the size** (0.77 MB against 1.48 MB), and its
  `TrainMC::doIteration` is 878 instructions against 2,547. It inlines less
  and makes more real calls, yet it is faster. Why is not investigated.

## What adopting clang would take (the developer decides)

1. **Build files.**
   - The bench Makefile uses `CXX ?= g++`, so it needs a default change or
     `CXX=clang++-20` on the command line.
   - `CMakeLists.txt` and the Cython `setup.py` would need clang and libomp
     too.
   - Every build machine then needs clang-20 and libomp; this would be pinned
     by the planned Nix flake.
2. **Re-baseline all timings.** Earlier entries' percentages are relative to
   GCC builds. The digests do not change.
3. **Keep GCC working,** or at least building, as a cross-check. The
   harness can compare the two after any change.

## Discussed with the developer

- **Reproducible toolchains.** pixi (conda-forge) would be the uv-like
  option. The developer prefers **Nix**; the learning curve matters less when
  AI does most of the work.
  - Plan: a Nix flake for the C++ toolchain (gcc, clang, libomp, make,
    valgrind, gprofng), with uv kept for Python and PyTorch. PyTorch wheels
    bundle CUDA, which avoids Nix's CUDA packaging problems.
  - Nix binaries link against Nix's glibc, libstdc++ and libomp, so timings
    must be re-baselined inside it and the digests rechecked.
  - Installing Nix is a system change the developer makes.

## Adopted (the developer's decision, 2026-09-24)

`019ee6d` makes clang++ 20 the default in the bench Makefile, `CMakeLists.txt`
and `setup.py`. Each file picks clang only when no compiler was given, so
`CXX=g++` (or `CMAKE_CXX_COMPILER`, or `CC`/`CXX` for setup.py) still selects
GCC. The Makefile needs an `origin` check, because Make predefines `CXX` and
the old `CXX ?= g++` never took effect.

Checked after the switch:

- **Bench gates:** golden, verify, rulecheck and the sample digests on seeds
  1–4 are unchanged.
- **CMake:** it picks Clang 20.1.2, and the unit tests pass 45/45 with clang
  as well as g++.
- **Cython:** the extension compiles with clang++-20, links libomp, and
  loads. The import then stops at `import keras` in `main.pyx`; this machine
  has never had TensorFlow.

The build-comparison harness now takes `base` from the Makefile default, with
`gcc13` as an explicit arm. `BASE_CXX_BIN=g++` restores a GCC base for the
GCC-only PGO arms. **Timings recorded before this entry are g++ 13 numbers.**

The unit tests and `Tourney` needed the same portability fixes as `Trainer`:
initialized VLAs, and `std::sort` without `<algorithm>`, which GCC's headers
had pulled in by accident (`52151b2`).

## Found on the way: a crash since entry 16 that no gate covered

Checking that the CMake unit tests build with clang showed they **segfault
with g++ too**, at `TrainMCTest.FewPerMove`, while `main` passes all 45.
`git bisect` pointed to `cba9c7a`, entry 16 (children's statistics mirrored in
the parent).

- **Cause:** the move-applying `Node` constructor now always called
  `parent_->addChild(this)`. But `TrainMC::chooseMoveOpening` and
  `chooseMoveNormal` build a new root that way, with `parent == nullptr`, when
  the chosen move has no visits. That happens with one search, or when every
  root move is a proven loss.
- **Fix (`87533d8`):** register only when there is a parent. A root keeps its
  statistics in its own fields, as the other root constructor already did.
  Afterwards:
  - unit tests 45/45;
  - the TrainMC tests are clean under ASan and UBSan;
  - golden, verify and sample digests unchanged.

  A full-suite sanitizer build hit a g++ 13 internal compiler error, a GCC bug
  unrelated to the code.
- **Why no gate caught it:**
  - golden, verify and the sample digests all run at 1,600 searches, where
    "every root move proven lost" evidently never happened in the games they
    play;
  - the unit tests had not been run on this branch.

  The Cython training build never ran this code (the cloud generations
  predate entry 16), so no training run was affected.
- **Lesson: the CMake unit tests are now part of the gate** for engine
  changes, alongside golden, verify, the sample digests and the assert build:

  ```
  cmake -S . -B /tmp/cm && cmake --build /tmp/cm -j 8 && /tmp/cm/CorinthoAI
  ```

  They cover small search budgets and edge paths the bench never reaches.
